# 主线 · Mainline

一个只在本机运行的个人秘书桌面客户端。适用于两个科研组、个人科研、创业探索和生活安排。

## 打开和停止

可从 GitHub [直接下载单文件 EXE](https://github.com/qinq3132-cmyk/MainLine/raw/refs/heads/main/Mainline-Desktop/downloads/Mainline-2026-10-15-v9.exe)，放到自己选择的文件夹后双击运行；无需安装 Python。详细步骤见 [Windows EXE 安装说明](Windows-EXE-安装.md)。它是免安装桌面版，不是 Setup 安装器。v9 修复秘书新建项目、界面文字复制和回车发送。

本机验收过的文件夹版位于 `release/2026-10-15/Mainline/Mainline.exe`。使用文件夹版时必须保留同目录的 `_internal` 文件夹；不要只复制其中的 EXE。

关闭桌面窗口会停止前台服务；如果在设置中开启了“关窗后提醒”，Windows 会每 5 分钟在后台检查一次。以后再次启动会继续使用原有数据。源码方式运行 `server.py` 时，关闭浏览器不会停止服务。

打包版包含 Python 运行环境；桌面窗口需要可用的 WebView 运行环境。源码开发需要 Python 3.11 或更新版本，桌面入口另外需要 pywebview；PDF 读取使用 pypdf。界面不加载外部字体、脚本或图像。

## 页面和操作

- **四象限指挥台**：拖动事项改变重要／紧急归类，点选编辑，勾选完成。周期事项只在到期且未完成时出现；完成后从首页消失，到下一个周期再出现。今日节奏单独呈现时间安排。
- **项目**：采用“一级类别 → 二级项目”的结构。首页只显示类别和数量；点击类别，再点击具体项目，可单独编辑负责人和 0–100% 进度。在事项详情里点“设为独立项目”，可将该事项及同一周期的完成记录归入新二级项目，原记录保留。也可在类别下直接“新建项目”。选择“活动安排”后不显示进度；聚餐、会议也可直接作为类别事项记录。
- **周／月总览**：切换周计划、月全景，前后翻页，点选日期查看安排、截止和检查节点。拖动非固定事项到日期后确认具体时间。
- **长期成长**：目标卡片集中显示方向、持续投入、下一步、回顾与足迹。持续投入支持重复安排、完成后生成下一次和最近七天记录；未关联目标的习惯在“独立投入”区域展示，可编辑后关联。原有目标、投入和记录继续保留，旧 `#habits` 链接也会打开合并页面。
- **个人笔记**：按整体或具体项目记录反思、判断与进展想法，可搜索、续写、归档和恢复。笔记在本机数据库保存并进入备份与导出；秘书只在模型请求中读取最多 12 篇相关或近期笔记，每篇最多 1200 字，不把笔记当成已验证的当前事实。
- **项目文档**：具体项目可在项目卡片或详情中打开“项目文档”，关联任意可访问的本机文件夹；可用桌面版选择文件夹，也可输入完整路径。支持在关联位置新建根文件夹和子文件夹、放入不超过 20 MB 的文件、浏览文件名，并用默认程序打开常见文档。放入文件时复制，不改动原件；遇到同名文件不会覆盖。解除关联不会删除任何文件。
- **回收站**：恢复归档事项。恢复时仍检查原安排是否有冲突。
- **AI 秘书**：整理中文输入、讨论计划、回顾推进。新项目、新事项和更新建议可分别选择应用。应用成功后会打开新项目或相关事项；若没有成功应用，会保留建议并说明原因。建议区在应用成功后收起，处理结果保存在本机对话记录。对话框按回车发送、Shift + 回车换行，中文输入法选词不会误发送。
- **秘书附件**：Word、PPT、文件按钮接收 `.docx`、`.pptx`、`.pdf`、`.xlsx`、`.txt`、`.md`、`.csv`。文件库可选择、查看提取文字、移除文件；每次请求最多 5 个附件，每个 20 MB。不填聊天文字也可直接整理附件。
- **帮我安排时间**：根据偏好生成确定性的排期草案；保留固定约定与已有安排、午休、深度思考时段和缓冲。选择后应用。
- **提醒与跟进**：到期、逾期、安排即将开始、检查日期和重要事项停滞。通知保存在本机；可选用 Server酱给自己的微信推送需要行动的提醒。
- **专注**：事项详情中开始专注；暂停、继续、结束并记录真实分钟数。
- **偏好与数据**：工作时间、工作日、容量、缓冲、自动回顾、模型连接测试、数据库备份、JSON 导出和恢复。

空白安装只建立五个一级类别，不会添加虚构项目或任务。默认工作日为周一至周五，工作时间 09:00–18:00，午休 12:00–13:00，深度工作 09:00–11:30，每日排期容量 75%，事项间缓冲 15 分钟。可在偏好中更改。

## 模型配置与隐私

模型可直接在“偏好与数据 → 模型连接”中填写 API 根地址、模型 ID 和 API Key。独立配置保存在数据目录的 `llm-config.json`，可以通过 `MAINLINE_CONFIG` 指定其他文件，也支持 `MAINLINE_BASE_URL`、`MAINLINE_MODEL`、`MAINLINE_API_KEY` 环境变量。配置示例在 `llm-config.example.json`；环境变量覆盖文件中的相应字段。密钥留空保留原值，可勾选清除。独立文件中的 `api_key` 还支持 `{env:变量名}`。

OpenCode 是可选兼容入口，可在模型设置中关闭，不是运行前提。启用时读取本机 OpenCode 配置：`~/.config/opencode/opencode.json` 和 `opencode.jsonc`，以及 `OPENCODE_CONFIG` 指向的配置和当前工作目录的同名文件。JSON 与 JSONC 深度合并，同名字段以较后读取的文件为准。

支持配置中的 OpenAI-compatible / OpenAI 适配器和 `/chat/completions` 接口，支持直接密钥、`{env:...}`、`{file:...}` 和 OpenCode auth.json 的 API 密钥记录；不支持 OAuth 登录凭据。模型切换在网页右侧，默认优先使用配置中的 GLM-5.3 HTTPS 接口。

GLM-5.3 请求使用轻量思考并预留结构化结果的输出空间，参数依据 [Z.ai 官方文档](https://docs.z.ai/guides/llm/glm-5.3)，避免秘书整理时将输出长度全部消耗在思考中。

API 密钥由后台读取，不返回浏览器，也不加入任务数据库和任务导出。手动密钥保存于本机独立配置文件，该文件不加密并被 Git 忽略；OpenCode 密钥仍由兼容入口只读使用。模型请求会发送这次请求所需的项目、未完成任务、长期目标、偏好与输入，以及最多 12 篇相关或近期笔记的节选给选定的服务商；附件仅发送本次选择的文件文字。项目文档的本机路径和文件内容不会因关联文件夹而发送给模型。聊天输入在提交时写入本机数据库，即使模型请求失败也保留；秘书可从保存的历史聊天中检索相关片段用于后续讨论。默认自动回顾在每天 08:30 之后后台运行时准备一次；没有未完成事项和活跃目标时不调用模型，可以关闭。

附件按正文段落、幻灯片与讲稿、PDF 页码标记来源。读取文字，不识别图片、扫描页和图表布局；旧 `.doc` / `.ppt` 需要先另存为新格式。每个文件保存前 12 万字符，每次模型请求单文件最多 3 万字符、合计最多 6 万字符；超出部分明确标记为节选。

服务只绑定 `127.0.0.1`，不能从外部电脑直接访问。网页和后台接口检查 Host、Origin 和自定义请求头，不提供公开访问入口。

## 持续运行与提醒边界

后台每分钟检查一次提醒，网页每 30 秒读取新状态。**后台运行但网页关闭时，提醒仍会入库；浏览器桌面通知需要网页保持打开并允许通知。** 在 EXE 设置中填入自己的 [Server酱 Turbo SendKey](https://sct.ftqq.com/docs/getting-started/sendkey/)，保存并开启微信提醒后，可选择“开启关窗后提醒”。这个按钮会创建 Windows 定时任务，每 5 分钟检查一次；关闭功能会移除任务。电脑需开机且登录；关机、睡眠或离线期间无法即时发送。

微信只推送安排即将开始、今天到期、逾期和进度检查提醒；同一轮合并。按免费档本机限制每天最多 5 次发送尝试，测试消息和失败请求也占一次，不自动重试；超出额度的提醒仍留在本机。默认不发送事项名称；主动开启后也只发送事项名称，不发送负责人、备注或附件内容。SendKey 只写在本机数据目录的 `serverchan-config.json`，不进入数据库、导出、EXE 或 Git。服务商的[当前额度说明](https://sct.ftqq.com/docs/getting-started/faq/)以官网为准。

自动回顾不会自行写入任务、移动会议或向别人发送消息。缺少的项目进度依据需要你提供；模型不会直接读取组员实验系统。

## 保存位置和备份

数据默认在 `%LOCALAPPDATA%\Mainline\data\desk.sqlite3`，可用 `MAINLINE_DATA_DIR` 覆盖，开启 SQLite WAL。已有数据库不会被新版 EXE 覆盖；首次运行新版本会在 `backups/` 自动创建升级前数据库快照。若新版 EXE 放在此仓库目录内且桌面数据目录为空，会从旧 `personal-desk/data` 安全复制数据库与附件，旧目录保持原样。恢复 JSON 前也会自动保留一个完整数据库备份，恢复操作在事务中提交。

秘书附件原件在 `data/attachments/`，聊天、日程、任务、项目、目标、笔记、回顾和提醒记录在数据库中。项目文档在你自行选择的外部文件夹中；数据库和 JSON 备份只保存关联路径，**不会备份外部文件夹里的文件**。迁移电脑时需单独复制这些文件夹并重新关联位置。JSON 导出包含数据库记录及秘书附件提取文字，不包含原件二进制或密钥；复制整个 `data` 目录可以同时备份秘书附件原件和本机配置。归档笔记只标记状态，不删除正文。旧版 JSON 备份可继续导入，未包含笔记等新字段时保留当前相应记录。

关闭后台后可以复制整个 `data` 目录做额外备份。手动恢复数据库文件前应先停止后台，并保留原数据库和 WAL 文件。

## 验证

`python -m unittest discover -s tests -v` 检查冲突、连续时间、重复事项、原子排期、备份恢复、API 边界等实际行为。`node --check public/app.js` 检查页面脚本语法。

`node tests/test_growth_ui.cjs` 检查两级项目浏览、具体项目进度、活动免进度、目标与重复投入归组，以及旧数据兼容行为。

开发启动：`python server.py --port 5179`。测试可以使用 `--data-dir` 指定隔离数据目录，避免污染真实任务。
